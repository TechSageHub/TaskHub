# ADR-0002 — CSRF: double-submit token + SameSite=Lax

- Status: accepted
- Context: Cookie auth exposes unsafe endpoints to cross-site request forgery.
  Options: (a) synchronizer token in server state, (b) double-submit cookie,
  (c) SameSite=Strict only, (d) custom-header-only.
- Decision: (b) + Lax. Readable `taskhub_csrf` cookie echoed back in `X-CSRF-Token`;
  enforced on POST/PUT/PATCH/DELETE. `SameSite=Lax` blocks cross-site cookie sends
  for fetches; `HttpOnly` on the session cookie keeps XSS from stealing it.
  `Secure=SameAsRequest` so local HTTP dev works; production sets `COOKIE_SECURE=Always`.
- Options considered: synchronizer tokens (more server state per form — overkill);
  Strict (breaks top-level navigation UX); header-only (weaker without token binding).
- Consequences: SPA must read cookie + send header (done in `api()`); 403 on mismatch.
- Follow-ups: re-evaluate Strict if top-level flows allow; add Origin/Referer checks
  as extra signal (R2).
